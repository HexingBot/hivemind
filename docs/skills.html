Skills & Capability Packs

Hivemind is a small orchestration core plus a set of skills — focused playbooks the agents load only when relevant — and capability packs, optional add-ons a project installs on demand. This page explains the newest ones in depth: assimilate, the design pack, and the core skills underneath.

NEW · WAVE 1

assimilate — adopt a third-party skill, safely

The skills ecosystem is full of useful third-party skills — but pulling someone else's instructions into your agent is a supply-chain decision. Assimilate is the pipeline that lets Hivemind adopt an external skill without ever trusting it blindly. Instead of installing from the internet at run time, it vendors a pinned, vetted copy you own — so an upstream repo changing, disappearing, or turning malicious later has zero effect on you.

The gate — nothing lands without your sign-off

fetch a pinned copy  →  license (from the real LICENSE text or the GitHub API — never a self-declared label)  →  pattern scan (shell / network / credential access / obfuscation)  →  reviewer reads the actual content, including its instructions, for prompt-injection  →  YOU approve  →  adopt (owned copy + provenance + integrity hash recorded)

No approval → nothing is written. This is a hard invariant, proven by test: no code path adopts a skill or records it without an explicit approval — not even a permissively-licensed one.

Why a license is not a safety signal

A permissive license (MIT, Apache-2.0, …) only removes the legal blocker to vendoring — it says nothing about whether the code or instructions are safe. And a license: MIT line in a skill's own metadata is just editable text anyone can type. So in Hivemind, license is decision-support on a review card, never a trigger to adopt. Classification comes only from matched license text or GitHub's own detection; the safety decision is a separate, mandatory content review plus a human yes.

Two-stage: own, then activate

Assimilation writes the vetted copy to a staging area you own (assimilated-skills/<id>/) with a provenance block — origin, pinned commit, SPDX id, a sha256 integrity hash, and a timestamp. A separate reconciler then materializes it into the live .claude/skills/, and can cleanly remove it later. Ownership is tracked as edges, so a skill shared by two packs is never deleted while either still needs it.

# vet a skill (dry run — reads & classifies, writes nothing)
node bin/assimilate-skill.js \
  --url https://github.com/greensock/gsap-skills \
  --subdir skills/gsap-core --resource-id gsap-core \
  --pack design-power@0.1.0

# → { spdx_id:"MIT", detected_via:"license-file",
#     status:"pending_approval", integrity:"sha256:…" }
#   nothing written until you add --decision approve

Status: the adoption mechanism, license detection, ownership, and the human-gate are shipped (Wave 1). The content pattern-scan + reviewer layer is the next ticket — until it lands, assimilate runs as a safe vet & stage tool that never adopts without you.

CAPABILITY PACKIN DESIGN

Diseño Poderoso — the design pack

The first capability pack: an interview-driven design engine. Before generating anything, it profiles the project, scores its complexity, and activates only the design resources that project actually needs — in the right order.

Five phases

0 · base questions (what is it, for whom, how visually powerful, stack) → 1 · conditional questions (only what's relevant — canvas? motion? references? research?) → 2 · complexity score → tier LIGERO / MEDIO / COMPLETO → 3 · toolset selection (art direction, design system, components, motion, assets, testing) → 4 · pipeline runs the chosen steps in canonical order.

It's built for a Vue + Vite + Phaser + Firebase stack and knows the sharp edges: shadcn/ui is React-only so Vue projects route to shadcn-vue; on a Phaser game the UI skills apply only to the HTML/DOM layer (HUD, menus, overlays), never the canvas render; and the interview short-circuits when the project is simple, to avoid question fatigue.

Safe by construction

Every design resource the pack wants to bring in — skills like GSAP, MCP servers like shadcn-vue or Playwright — flows through the same assimilate gate above. The pack proposes the toolset; a human still signs off on any install. Skills adopt now; MCP servers are a planned Wave 2 (they carry an extra restart/approval seam).

CORE

The core skills

These load automatically or on demand as the orchestrator works a ticket. Each is a focused playbook — a few hundred tokens up front, deeper detail pulled in only when needed.

orchestrator-routing

The non-negotiable session-resume contract and the full operating manual for the orchestrator: delegation protocol, developer spawn modes, reviewer isolation, the UAT procedure, ticket-update protocol, and the verification-tier rubric. Loads at the start of every chat.

the impl-* manifests (Spine)

Six language-agnostic blueprints generated before code on core tickets — API contracts, block tasks, component catalog, project structure, screen specs, state schemas — plus manifest-verifier, the deterministic cross-manifest coverage gate.

deep-research

A four-lens research sweep (official docs, real-world examples, community pitfalls, alternatives) fanned out in parallel with schema-validated claims, then synthesized and critiqued for completeness.

deep-review

Multi-agent adversarial review for release gates and large diffs: four dimensions (AC-compliance, correctness, security, test-adequacy), each finding then adversarially verified before it counts.

graphify

Build, query, and inspect the project knowledge graph — nodes and edges under knowledge/graph/, visualized via the board's /graph view.

mcp-server

How to build, bundle, register, and test a minimal stdio MCP server in Node with the official SDK — the pattern behind Hivemind's own task server and any new one.

tech-training-template

When the researcher meets an unfamiliar stack, it copies this template to author a reusable skill — so the whole crew is “trained” on the new tech cheaply.

context-monitor

The statusline/hook contract for context-window monitoring, snapshotting, and pause/resume handoffs — how long sessions stay coherent across compaction.
